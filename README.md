# Дипломная работа. Часть 2
## Задание 2. Автотесты для API

### Назначение тестов
Автотесты предназначены для проверки корректности работы API сервиса Stellar Burgers: валидации входных данных, обработки ошибок

### Что тестируется
Тестируются эндпоинты API для Stellar Burgers.
* `Регистрация пользователя` (tests/test_create_user.py)
    * test_create_user_success — успешная регистрация с уникальными валидными данными (email, пароль, имя);
    * test_create_user_existing_email — отказ в регистрации при использовании существующего email;
    * test_create_user_missing_field (параметризованный) — отказ в регистрации при отсутствии одного из обязательных полей (email, password, name).

* `Авторизация` (tests/test_login_user.py)
    * test_login_success — успешная авторизация существующего пользователя, получение токена;
    * test_login_invalid_email — отказ в авторизации при использовании несуществующего email;
    * test_login_invalid_password — отказ в авторизации при вводе неверного пароля.

* `Создание заказа` (tests/test_create_order.py)
    * test_create_order_with_auth_and_ingredients — Успешное создание заказа с авторизацией и ингредиентами;
    * test_create_order_without_ingredients — отказ в создании заказа при пустом списке ингредиентов (статус 400);
    * test_create_order_with_invalid_ingredient_hash — реакция API на передачу невалидного хеша ингредиента (статус 500);
    * test_create_order_without_auth — поведение API при создании заказа без авторизации (статус 200 — в соответствии со спецификацией Stellar Burgers, авторизация для этого эндпоинта не требуется).

#### Для покрытия сценариев использованы:
- параметризация (@pytest.mark.parametrize) — для компактного тестирования комбинаций входных данных и граничных случаев;
- фикстуры (conftest.py) — для подготовки и очистки тестовых данных (создание/удаление пользователей, получение актуальных ингредиентов);
- Allure‑метки (@allure.title, @allure.suite) — для структурирования отчёта и читаемости результатов.
